## B. 原因和证据

| 问题 | PR #3 原型的证据 | 游戏中的影响 |
| --- | --- | --- |
| 控制状态可能未稳定 | 两个控制点可同一时刻 DOWN，默认 40 ms 后音键 DOWN，控制保持到 80 ms | 若任一控制在 UP 生效，音键可能先于状态改变。两个控制同帧的取样结果仍需录音和画面判定 |
| 密集段节奏持续推迟 | 原型完整延长短音，在每个音符后预留固定 40 ms。没有用可裁剪的前音时值吸收下一个音的准备时间 | 预计节奏损失可由计划复现。具体漏音和粘连需比较游戏录音 |
| 暂停使派发迟到指标虚高 | helper 会顺移后续截止时间，应用按未经暂停修正的起点和计划相减 | 旧日志无法直接用于有暂停的音准或节奏比较 |
| 旧版可能集中补发 | 两秒内的迟到仍可立即开始下一组触摸。前一组晚结束时，已过期的下一组可立即派发 | 新版按实际释放执行物理间隔，超预算终止并报告剩余 |
| 长曲停止响应受上传影响 | 原型持有写锁逐个发送 ITEM，直到 RUN 后才启动停止监视。回报队列无上限 | 新版通过有界块、逐块确认和独立心跳解决这个运行路径 |
| 转换阶段就可能少音 | MIDI 选轨、截断、单音化和音域各有独立损失。一个保留源音还可被切成多个片段 | 逐阶段报告保留、裁剪、丢弃和未映射。识别某首在线曲谱的具体根因仍需源谱及实测 |

PR #3 的原始头提交 `ce25766` 在 Android Kotlin 编译时因可空 DOWN 时间戳直接相减失败。现有在线曲库和游戏内音乐中心分支都是该提交的祖先。

rc.1 在游戏内播放 B-full-360 时，1× 在 279/360 个已完成音后触发 40 ms 迟到保护，2× 两次在 29/360 和 36/360 后触发。三次均收到释放确认，Android 输入队列随后无活动触点。rc.2 对有限的短时迟到顺移后续时序，从剩余休止逐步恢复。触点时值和最短松键间隔继续受物理下界约束。

rc.2 的 B-full-360 2× 完成 360/360。1× 完成 342/360 后收到取消回报，操作员确认始终在口琴界面且没有操作。该次缺少环境校验原因。rc.3 将焦点查询移出界面线程，以同一快照保留窗口身份和时间戳。失败或不可解析的查询不刷新有效期，明确失焦和同包窗口变化会触发停止。记录显示、锁屏、Root 状态、权限、焦点丢失与焦点过期等独立原因。

rc.3 真机 1× 仅完成首音，随后收到 helper 的释放拒绝回报。操作者说明这轮没有录屏，停止后出现释放待确认。事后确认 helper 已退出，Android 无活动触点。后来看到的系统通知窗口只说明检查时的焦点。终止当时的焦点及注入拒绝原因仍待查。

## C. 核心修改

- `PlaybackPlanner` 与 `RootPlaybackTiming` 保留每个脚本音符的原谱起点及最终计划，考虑可用空隙、前音可裁剪时值和指法切换成本。双控制依次完成音区和半音动作。相同音键的释放地板在 1× 和 2× 均为物理时间。
- `RootSequencePlanner` 编译顺序触点。首音所需的控制预备段安排在音乐时钟前，保留首拍与第二个起音之间的谱面间隔。单音 DOWN、UP 和每次控制释放由 `RootSequenceTimeline` 和 `RootTouchTimeline` 在 helper 内调度。对长时间等待采用可唤醒的单调时钟休眠。
- `RootSequenceProtocol`、`RootGestureConnection` 和 `RootTouchMain` 使用版本化编号、32 音一块的请求与确认、完整提交及有界回报。IPC 回报拥塞会中止派发，helper 不等待 UI 处理逐音回调。单会话上限为 100,000 音。
- `CalibrationOverlayService` 校验目标 UID 对应的游戏焦点、窗口身份、校准显示、屏幕交互和浮窗位置。暂停边界保留已完成前缀，继续前要求用户核对游戏控制状态并重新校验环境。失焦、停止或异常中止会使应用跟踪的控制状态失效。
- `RootBackend` 和 `RootReleaseGuard` 在派发前记录活动会话，等待 helper 释放和终止回报。应用进程重启后保留未确认状态。无终止回报时阻断新会话。明确结束且报告释放失败时，允许验证 Android 触点为空。
- MIDI 解析和 DFHS1 转换沿用现有导入、选轨、节拍和脚本格式。脚本 v2 新计数向后兼容，旧记录缺失的数据保持未知。音高诊断保留原谱音高和等音高指法选择。
- 无障碍仍有单独的逐手势路径。若 Root 预检或初始化失败，选择无障碍后端并重新预检，使用无障碍对应的时序。待确认的 Root 释放会阻断启动。游戏内曲库切换可装载选中曲目，若上一首中止后状态未知，先核对音区和半音。

### Windows 源码对照

- Dr-hydra 的 `Optimizer.cs` 对每个音高枚举等音高指法，用相邻键位和修饰键成本做动态规划。`KeySequence.cs` 排序绝对时间并优先释放等时事件。`Player.cs` 使用 Stopwatch、短休眠和末段自旋，在暂停与结束时释放所持键。 [源码提交](https://github.com/Dr-hydra/Delta-Force-Harmonica/tree/87447eec77bcc7318f0cf96f003d01ae21e1849c/desktop)
- ChickenD233 的 `MidiLoader.cs` 将 MIDI 按轨道和声道提取并应用 tempo map。`PlaybackEngine.cs` 提前派发变更、预留最短按住和释放、跟踪重复键，并在暂停和停止时释放。它按住鼠标修饰键控制音区和半音。 [源码提交](https://github.com/ChickenD233/harmonica-auto-player/tree/a14335c86a17080186bbf781f3156e65e22c4ad2/HarpAutoPlayer)

### Android 候选参数

| 物理量 | 候选值 | 验证边界 |
| --- | ---: | --- |
| 控制按住 / UP 后稳定 | 44 / 36 ms | 适用于先放再吹的候选序列 |
| 每组 DOWN/UP 计划传输余量 | 12 ms | 各硬地板之外的预算 |
| 最短音键按住 | 45 ms | 用户最短时值配置可提高此值 |
| 异键 / 同键 UP 到下一次按下 | 18 / 42 ms | 控制动作只能出现在前音释放后 |
| DOWN 常规迟到 / 附加恢复窗 | 40 / 120 ms | 有限重排，严重卡顿终止并保留未执行计数 |
| 恢复阶段最大净顺移 | 计划时长的 2%，最少 120 ms，最多 2 秒 | 超预算终止，后续空隙可消化已积累延迟 |
| 协议确认 / 心跳租约 | 1,200 / 4,000 ms | helper 关闭回报和队列受控 |

上述输入参数待游戏逐音发声数据确认。候选使用 Android 的状态按钮语义和可唤醒截止时间。面板准备、播放计划编译与实际注入使用单调时间。

预检报告曲谱总延长。如果延长量大于 2 秒及原谱时长的两倍，当前选定速度无法启动，界面提示降低倍速或换用较稀疏的曲谱。

## E. 测试

构建环境为 Temurin 21.0.12.1、Gradle 9.9.1、AGP 9.5.1、Kotlin 2.4.21、SDK 37.2、Build Tools 37.0.0。真机为 Xiaomi 23127PN0CC，API 36，1200 × 2670，480 dpi。

- rc.3 JVM 347 项通过，0 失败，0 跳过。包括长计划上传、协议不一致、停止、暂停顺移、Root 失联、迟到恢复、严重迟到终止，以及焦点缺样、失焦和授权重核。
- Debug、Instrumented、Instrumentation APK 和个人签名 Release 构建通过。Lint 0 错误、86 警告、7 提示。
- 守护脚本执行了常规隔离回归，首轮 32 项常规用例通过，3 项新增 Root 用例在测试布局校验中失败。修正测试布局后，混合复跑出现 Compose 操作超时，设置用例停滞，仅终止了隔离应用进程。独立复跑三项 Root 用例全部通过。
- rc.2 的 360 音两档、暂停继续及停止用例通过。8 和 16 音用例首轮出现释放回执拒绝，Android 随后报告无活动触点。同版本通过 `-RootShortOnly` 复跑该用例并收到释放确认。
- rc.3 的 8 和 16 音用例通过，使用隔离包复测两档触点，包括全部 DOWN/UP 和释放确认。离线安装保护 21 项、模拟设备工作流 8 项和 APK 输入保护均通过。

## F. 安全与兼容性

隔离触点验证使用独立宿主 UID。正式包经同证书覆盖安装，安装前后 appId、首次安装时间及悬浮窗授权一致。校准、Root 授权记录及浮窗设置的摘要一致，rc.3 安装前后曲库目录 48 个文件的摘要一致。候选可冷启动并且只有一个 Launcher 入口。

rc.3 的释放保护保持生效。候选验收结束时 Android 报告无活动触点，helper 已退出，临时详细日志设置已恢复。现有播放锁由设备重启解除。
