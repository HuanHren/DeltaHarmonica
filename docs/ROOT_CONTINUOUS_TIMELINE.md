# Root 连续触控调度：实现说明与验收边界

状态：**源码已接入，尚未完成 Gradle 编译、Android 16 真机和游戏逐音发声验收。** 请勿把此分支直接视为已验证正式版。

## 为什么修改

旧链路在每个音符前都由应用进程重新发送一组手势，并等待 Root 子进程回传 DONE，之后才继续规划下一个音符。密集半音、高低音切换时，额外的跨进程等待和控制触摸可能造成延迟。

Windows 桌面版的做法可作为思路：事先排好修饰键与音符时间轴，设置控制键提前量、相邻音键松按间隔和最短按下时间。**但 Windows 通过 SendInput 操作键鼠，Android 游戏里的音区/半音是状态按钮，不能把 Windows 修饰键“持续按住”机制原样移植。**

## 当前实现

- `AppViewModel`：选中 Root 时优先生成组合触摸计划，最短音键按压 **45 ms**，相邻音符计划额外间隔 **40 ms**。
- `RootSequencePlanner`：把已校准的 8 个音键和音区/半音控制点转换成完整 Root 时间轴。沿用现有 `CombinedGesture`（控制键默认提前 40 ms、保持 80 ms），不改变乐器状态语义。
- `RootGestureConnection`：使用 `QUEUE / ITEM / RUN` 一次发送整段计划，`START / EVENT / END` 回传起始时刻、逐音 DOWN/UP 与最终结果；提供 `PING` 活性监测、`PAUSE / RESUME / STOP`。
- `RootTouchMain`：在一个特权进程内以 `SystemClock.uptimeMillis()` 为基准执行整段计划；两个音符之间不等待应用回调。保留一个音键占用规则，控制点允许与音键重叠；触控异常时尝试安全取消并停止。
- `PlaybackRunner` 与 `CalibrationOverlayService`：根据信任的 Root 会话使用连续分支，进度/暂停/结束回调仍经统一播放器传播。无障碍模式继续使用已有手势路径。
- 暂停仅在当前音符完成后生效，不截断长音；恢复保留原谱的剩余间隔。单次输入调度滞后超过 2 秒时停止，防止集中补弹过时的音符。

该实现是**连续时间轴 + 分音符触控流**，不是把所有音键长期按住。音符仍按规则 DOWN/UP 重触发，否则无法可靠地产生连续发声。

## 仍需实测

1. **构建**：在项目 Windows 环境运行 `gradlew.bat testDebugUnitTest assembleDebug lintDebug`，再构建正式签名 APK。
2. **游戏切换时序**：确认音区、半音到底在 DOWN 还是 UP 时生效；当前 40/80 ms 组合数值是候选值，不是手机实测保证。
3. **连续调度**：8/16/整曲在 1×、2× 下通过音符累计、DOWN/UP、暂停/继续、STOP 与退出游戏释放。
4. **发声闭环**：用真实复杂曲谱采集游戏音频，对比输入事件计数、实际发声音高和数量，不能用 `END OK` 冒充无漏音。
5. **高压和异常**：快速半音/音区交替、重复音键、长短音混合、Root 断开、进程退出、失焦与异常注入。
6. **兼容性**：不清空现有曲库、已保存校准、偏好与签名证书；必要时允许回退现有无障碍输入路径。
